## What changed

Adds `src/core/separation.test.ts`, the Separation row of spec 10.2. fast-check builds random mixes of `it` and `zh` games and review rows, then runs them through storage, sync merge, replay and the Progress selectors. Each language sees only its own rows (3.4.1), and every review row points at a game of its own language (3.4.2). Test only: no app code changes.

Each property runs 40 times:

- **Storage, reading.** Every per-language key (`guest:{code}`, `user:{userId}:{code}`) holds every language's rows, plus one row in a language the app doesn't have. Each store loads only its own, as a guest and after switching to a signed-in user.
- **Storage, writing.** Both languages record games, review rows and round ends in a random interleaved order. Each key saves only its own rows. Signed in, every review row in the shared outbox comes after a game of its own language; a guest queues nothing.
- **Sync merge and replay.** A fake Supabase returns both languages' rows mixed together, plus an unknown language. After `syncNow`, each store and saved key holds only its own rows. Each language's uploaded cards match a replay of its own log alone, `log_count` counts only its rows, and no card has another language.
- **Progress selectors.** On every path above, the Due list, the Mistakes tab and Chi è?'s dashboard totals match what that language's own rows alone would give, and show only that language's ids.

Two small tests guard the checks themselves: the two languages' ids are disjoint (3.4.3), so a crossed row shows up as a foreign id, and the shared assertion fails on a store that holds both languages' rows.

To confirm the test can fail, separation was broken in a scratch copy two ways. Letting a store keep every language's rows failed the reading and sync tests. Having `pull` replay one combined log for every language failed the sync test.
